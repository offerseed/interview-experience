### Q1：请先做一下自我介绍。

- 标签：开放题

### Q2：为什么不读博士？

- 标签：开放题

### Q3：本科和硕士都是主要研究什么？

- 标签：基础

### Q4：在校或自学接触过哪些人工智能、大模型知识？

- A：系统学习过机器学习、深度学习课程；近期重点自学 vLLM 相关技术，当前实习主要围绕 SGLang 展开，对框架实现和适配进行了深入研究。
- 标签：基础

### Q5：在XXX主要负责什么工作？框架层和算子层都有涉及吗？

- A：主要负责芯片上的 vLLM、SGLang 迁移适配，框架层、算子层的开发和测试都参与过。
- 标签：核心

### Q6：开源框架已经完成基础适配，为什么公司还要重新做一版？

- A：vLLM、SGLang 原生面向 NVIDIA CUDA 和 GPU 生态，不能直接运行在自研异构上。算子、通信原语和存储架构不同，需要重新适配；开源框架也没有针对架构、片上存储、多卡互联 All-to-All、张量计算单元做极致优化，直接运行可能出现延迟高、吞吐低或显存/片上内存溢出。实际还需要结合客户模型（如 Kimi、Qwen3.5-VL）、GDN/MTP 路由、多模态视觉模块及垂直业务需求补齐功能。
- 具体提到：PagedAttention 分离机制无法直接迁移，LM Cache缓存方案需要重新调试和选型。
- 标签：核心

### Q7：流水线逻辑是否基本通用，只需要适配算子和通信模块？

- A：整体理解基本正确，但缓存和内存管理模块也需要结合硬件单独改造，不能只替换算子与通信实现。
- 标签：核心

### Q8：具体落地过哪些改造、调试工作？

- A：主要包括四类工作：
  1. **精度与性能测试**：跑完整测试集，区分框架 Bug 和底层算子缺陷；算子问题提交算子组，框架问题自行修复。Agent 数据集的输出波动较大，曾定位到硬件优化选项未开启，导致推理超时并触发精度报错，补齐配置后基本解决。
  2. **性能瓶颈定位**：使用芯片 Profiling 工具生成性能热力图，梳理推理调用链并与基准链路对比；链路一致时继续核对算子输入输出张量，以区分算子和调度问题。
  3. **框架 Bug 修复**：处理过精度丢失和模型输出重复问题，后者最终定位为抢占式 Prompt 调度缺陷：上下文队列反复复用抢占缓存时，历史输出会重复叠加。
  4. **框架迭代开发**：重点参与 Qwen3.5 的迁移，改造 GDN 门控线性注意力模块，逐一对齐调度链路元数据，并参与 All-to-All 分布式通信算子适配。
- 其他经历：在部分算子尚未完成时手写简易替代算子；接触编译链路；修复过 Transform Engine 训练算子库底层 Bug；使用自研性能分析工具定位瓶颈。
- 标签：核心

### Q9：为什么说 SGLang 的 Radix Attention 更适合 Agent 长对话场景？

- A：vLLM 的核心缓存机制是哈希寻址，每次读取 KV 缓存需要进行哈希查找；Radix Attention 使用树形结构存储 KV，可以一次性填充整段序列缓存，减少反复检索。车载和智能座舱 Agent 上下文较长、KV 缓存复用频率高，因此更适合这类场景。
- 标签：核心

### Q10：vLLM 也可以外接 Radix Attention，为什么还要单独投入 SGLang 适配？

- A：理论上可以集成，但 vLLM 的调度和缓存架构基于哈希机制设计，改造成本较高。SGLang 原生搭载 Radix Attention，调度逻辑和算子接口更容易与自研 MLU 深度耦合，开发维护成本更低。
- 标签：核心

### Q11：手写算子时深入过编译链路吗？

- A：接触过一部分。通过 Transform Engine 算子库 Bug 定位完整走过编译调试流程，并结合自研性能分析工具排查问题。编程范式与 CUDA 比较接近，后续新人入职也会统一培训。
- 标签：核心

### Q12：为什么不选择继续转正？

- A：已发放正式 Offer，团队也支持自己外出了解其他机会并愿意提供实习背书。希望多接触不同行业，车载智能驾驶和座舱大模型是很感兴趣的方向，因此希望尝试蔚来的机会。
- 标签：开放题

### Q13：熟悉通义千问 3.5 的网络结构、Attention 和 GDN 吗？对 K3 系列模型有了解吗？

- A：近期参与过 K3 的快速适配并研读过技术报告。Qwen3.5 使用混合注意力架构，GDN 门控线性注意力结合稀疏化和 KV 缓存压缩，能够降低长序列显存占用，也是适配中改动较多的模块。K3 主要强化门控线性注意力的稀疏压缩能力、引入正则化结构，并优化量化方案；对 4bit、8bit 量化支持较好，但 FP16 支持相对较弱，量化移植投入较多，但并非本人主要负责。
- 标签：核心

### Q14：过往以推理优化为主，是否对训练方向感兴趣？

- A：一直在自学训练相关知识，研读强化学习、预训练论文，实习期间也接触过少量训练算子调试，愿意向训练和推理全栈方向拓展。
- 标签：开放题

### Q15：团队训练体系是自研还是复用开源框架？

- 面试官介绍：采用混合架构，自研模块和开源框架都会使用。端侧落地需求特殊，开源方案多面向云端大模型，端侧算子、调度和内存优化不足，需要自研补充；前沿算法预研会复用主流开源框架。训练、微调链路按业务拆分为多条技术线，团队还会持续扩招训练方向人员。
- A：先向面试官了解团队技术栈和业务方向。
- 标签：开放题

### Q16：伪代码实现 GQA 分组查询注意力，核心计算逻辑是什么？

- A：通过对 K、V 张量执行 repeat 复制，让多组 Query 共享同一组 KV，从而体现 GQA 的分组逻辑。现场伪代码未严格展开分组数量、张量维度及对齐超参数，因为题目只要求梳理核心思路。
- 追问：代码中分组 Group 的逻辑在哪里？是否定义了分组数量和维度对齐？
- A：Group 逻辑体现在 KV 的 repeat 复制操作中，具体维度和分组参数在伪代码中省略。
- 标签：核心

## 经验总结

- **项目深挖重点**：AI Infra 岗位会同时追问框架、算子、缓存、内存、通信、Profiling 和硬件差异，需要能把具体 Bug 从现象、定位过程讲到修复方案。
- **推理框架与训练方向要连通**：有 vLLM/SGLang 迁移经验时，还应补充训练全链路、训练显存优化、存储调度和训练算子等知识，解释推理经验如何迁移到训练 Infra。
- **模型结构需要结合工程实现**：除了解释 GGDN、GQA、Radix Attention 等概念，还要说明 KV 缓存、量化、调度元数据和端侧硬件约束对实现的影响。
- **伪代码题要写出边界**：GQA 至少应明确 Query 头数、KV 头数、分组数、维度对齐和张量形状；即使题目允许伪代码，也建议把关键超参数和形状写清楚。
- **面试官风格**：围绕项目经历持续追问，关注真实参与程度和问题定位过程；后半程会介绍岗位职责，并直接反馈训练方向的能力缺口。
