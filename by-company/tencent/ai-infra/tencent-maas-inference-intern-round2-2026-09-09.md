## 二面 — 推理框架项目深挖与并行策略（时长未记录）

### Q1：请做一下自我介绍。

- 标签：开放题

### Q2：具体讲一讲事情和产出。

- A：围绕 vllm 和 sglang 两大模块开展模型与特性支持、算子开发和性能优化，适配千问 3.5、Kimi 等混合注意力模型，修复 prefill-chunk、prefill 等特性问题，并独立负责 MOE 的 all-to-all 通信特性。
- A：后期参与 Qwen 适配，负责 qwen3.5 框架适配和 MTP 支持；根据客户工况抓取算子输入输出、分析瓶颈并向算子团队提出优化需求，紧急场景下也会先完成初步实现。
- 标签：核心

### Q3：K3（Kimi 系列）模型的结构有什么特点？适配时需要处理哪些问题？

- A：K3 的 Attention 基于千问的 Gated Data-Dependent Attention，在此基础上增加可调节线性 Attention 的相关参数。由于 K2.5 已有 KD 相关实现，整体迁移较顺利。
- A：主要挑战来自模型参数规模较大，量化适配和模型部署会带来显存、算力及工程落地方面的压力。
- 标签：核心

### Q4：Kimi 会采用怎样的并行策略？如果采用 PD 分离呢？

- A：目前主要支持对称的 PD 分离，例如 4P4D 配置；框架负责实现对应功能特性，硬件侧通常使用 32 卡完成 Kimi 的部署和量化。即使不采用 PD 分离，也会结合 TP、DP 等策略。
- 标签：核心

### Q5：TP 和 DP 哪种并行策略更优？如何选择？

- A：需要根据客户业务指标组合调试。TP 规模增大通常有利于推理性能和 prefill 速度，但显存冗余也会增加，开启投机解码时整体效果可能更好；DP 规模增大有利于提升整体吞吐量。
- A：不存在绝对最优配置，应结合延迟、吞吐、显存和投机解码等要求评估多套 TP/DP 组合。
- 标签：核心

### Q6：了解 Context Parallel（CP）吗？K3 能否使用 CP？

- A：CP 是上下文并行，与 TP、DP 属于正交的切分方式，主要用于长文本场景。K3 理论上可以支持 CP，目前仍在迭代适配；此前 Review 过相关代码，也修复过 DeepSeek MLA 模型的 CP bug。
- 标签：核心

### Q7：KDA 层和 MLA 层可以同时使用 CP 吗？CP 的实现方式有哪些？

- A：认为可以同时使用。在寒武实现中，会先切分 Context 并分发到各卡，在进入 Attention 计算前再重组，属于伪 CP 实现。CP 还包括 PCP、DCP 等形式，当前部分细节仍不完善，整体属于 VCP（虚拟上下文并行）方案。
- 标签：核心

### Q8：CP 和 SP 一般有什么区别？开启 TP 时为什么经常搭配 SP？TP 的通信流程、横向切分和通信次数是什么？

- A：CP 与 SP 的概念容易混淆，对两者区别和 TP 底层通信细节掌握得不够深入；团队已实现相关模块，未直接参与底层实现。
- 标签：核心

### Q9：回到实习经历，实际落地做了哪些工作？

- A：主要负责 bug 修复、新特性支持、模型适配，以及精度和性能测试分析；重点完成千问 3.5 的 MTP 适配与支持，也参与千问、Kimi 等模型的测试。
- 标签：核心

### Q10：千问 3.5 的 MTP 做了哪些适配？

- A：在 MTP 解码阶段适配 GDN 的 Backend 逻辑。原生实现面向 NVIDIA 硬件，自研硬件的算子输入存在差异，因此需要迁移适配；同时补齐原生实现不支持的 Memory State 存储形式。
- 标签：核心

### Q11：如果调整 MTP 参数来提升 token 接受率，可以调哪些参数？

- A：可以减小 draft step，减少 Draft Model 一次生成的 token 数量，从而提升接受率，但会牺牲部分推测长度。
- A：当前主要支持 Eager 模式，一次推测三四个 token。
- 标签：核心

### Q12：如何评估算子是否还有优化空间、是否构成性能短板？

- A：对比算子理论性能值，参考同等算子在 GPU 上的性能，并结合多代硬件的代际算力差异评估。如果新一代卡理论算力约为旧代两倍，也可以观察实际性能是否体现出相应收益。
- A：曾对 Kimi 2.6 做性能分析，抓取算子信息，对比理论性能与实际运行性能，定位性能瓶颈。
- 标签：核心

### Q13：MFU 和理论性能值如何计算？

- A：硬件团队提供带宽、存储性能等基础参数，工具抓取算子输入输出维度后，结合输出维度、硬件带宽和存储性能等指标计算理论值及 MFU。
- 标签：核心

### Q14：K3 的适配开始了吗？当前性能大概如何？

- A：适配工作已经启动，目前性能大约对标 H20 GPU 的 50%。
- 标签：核心

### Q15：你有什么想问面试官的吗？

- A：询问优秀实习生和校招候选人更看重算法能力还是工程能力，以及推理框架深耕和底层算子优化哪个方向更有优势。
- A：面试官反馈团队两个方向都有；结合候选人经历，更偏推理框架层，而不是最底层算子优化。
- 标签：开放题

## 经验总结

- **项目深挖重点**：重点复习混合注意力模型（GDN/KD、MLA）、MTP、Memory State、MOE all-to-all、量化部署和 PD 分离等实际适配问题。
- **并行基础短板**：本轮对 CP、SP、TP 通信流程和横向切分回答不够深入，应补齐 CP/PCP/DCP 的区别、TP 与 SP 配合原因及通信原语。
- **性能分析表达**：需要能清楚说明理论 FLOPS、带宽瓶颈、MFU、硬件代际对比，以及从 profile 到算子优化需求的定位过程。
- **投机解码准备**：掌握 draft step、token 接受率、Eager MTP的关系，并说明接受率与吞吐之间的权衡。
- **面试官风格**：围绕简历项目逐层追问，重点考察真实落地深度、并行策略理解和性能分析能力；对未直接负责的底层模块会继续追问边界。
